1. Prepare a estação

  1. Extraia todo o ZIP. Não execute os arquivos dentro da janela do ZIP.
  2. Use Java 17 ou superior com compilador (JDK). No terminal, confira java -version e javac -version. Se faltar Java, avise o professor.
  3. Abra esta pasta no editor/IDE. Não crie declarações package. Edite somente Inventario.java, FilaCircular.java e Escalonador.java.
  4. Execute os testes pelo procedimento abaixo. O relatório entregue é uma fotografia inicial; depois de executar, ele é substituído pelo seu resultado.

Windows

Dê dois cliques em testar.bat. O terminal fica aberto para você ler o resultado.

Linux / macOS

Abra o terminal nesta pasta e execute:

sh testar.sh

Em qualquer sistema, com JDK

mkdir build
javac -encoding UTF-8 -d build Inventario.java FilaCircular.java Escalonador.java Testes.java
java -cp build Testes

Depois, abra relatorio.html ou pressione F5 no navegador. Salvar o Java não atualiza o relatório sozinho.

Se a compilação falhar, corrija o terminal antes de consultar o relatório: ele ainda mostrará a execução anterior.

Linux: seleção automática do Java

O testar.sh atualizado usa automaticamente o Java 21 quando ele está instalado em /usr/lib/jvm/java-21-openjdk-amd64. A seleção vale para a execução do script; basta rodar sh testar.sh.

Se aparecer “Unrecognized option: -m” em uma cópia antiga: no laboratório, o terminal estava usando outro Java. Se o caminho abaixo existir, execute:

export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
export PATH="$JAVA_HOME/bin:$PATH"
sh testar.sh

Não há espaço entre o hífen e version ao conferir java -version. Se faltar o compilador, avise o professor. Mais detalhes em AJUDA_JAVA_LINUX.txt.

Já começou a atividade? Ao atualizar o pacote, substitua somente testar.sh e acrescente o arquivo de ajuda. Preserve os Java e o registro de respostas que você editou.

2. Dividam os papéis

Em duplas: uma pessoa programa e outra testa/explica. Em trios: programação, testes e investigação. Troquem a cada missão. Antes de executar, registrem a previsão pedida em RESPOSTAS.md.

Missão 1 · Inventário corrompido

Contrato: vetor de inteiros com capacidade fixa, ocupação compacta e ordem preservada. Inserir aceita índices de 0 até tamanho, inclusive. Remover aceita de 0 até tamanho − 1. Remover devolve o valor retirado. Zero, negativos e repetidos são valores válidos.

Previsão: capacidade 8; itens [10,20,30,40,50]. Insira 25 no índice 2 e depois remova o índice 4. Qual o vetor final? Quantos valores precisam ser deslocados em cada operação?

Entrega: corrija a implementação, preserve os atributos e as assinaturas e passe nos 10 testes. Não use coleções prontas ou ordenação para substituir o deslocamento.

Explique: por que o sentido do deslocamento importa? Qual é o custo de inserir no início? E no fim quando há espaço?

Cheio: IllegalStateException. Índice inválido: IndexOutOfBoundsException. Capacidade não positiva: IllegalArgumentException.

Missão 2 · Lobby travado

Contrato: fila FIFO em array circular. inicio aponta para o próximo a sair; fim aponta para o último inserido. Inicialmente: início 0, fim −1, tamanho 0. Utilize tamanho para distinguir vazia de cheia.

Previsão: capacidade 4; insira A,B,C,D; retire duas vezes; insira E,F. Desenhe as quatro posições físicas e a ordem de atendimento final.

Entrega: faça a fila reutilizar posições e funcionar após vários ciclos. Inserir, remover e consultar devem ser O(1); não desloque elementos nem use coleções prontas.

Explique: por que atingir o fim do array não significa que a fila está cheia? Consultar é o mesmo que remover?

Cheia: IllegalStateException. Remover/consultar vazia: NoSuchElementException. Capacidade não positiva ou valor null: IllegalArgumentException.

Missão 3 · Servidor injusto

Contrato: todos os processos chegam no instante 0 e não há novas chegadas nem custo de troca de contexto. Cada vez utiliza no máximo quantum unidades. Processo incompleto volta ao final; terminado sai. Não altere o array de durações recebido.

Previsão: P1=5, P2=3, P3=1, quantum=2. Registre cada turno, o restante de cada processo, a ordem de conclusão e o tempo total.

Entrega: corrija executar e passe nos 10 testes. A fila desta missão usa ArrayDeque de propósito: ela independe da implementação da missão 2.

Explique: a ordem de conclusão tem que ser FIFO? Por que o tempo executado pode ser menor que o quantum?

Durações e quantum são inteiros positivos. Entradas inválidas: IllegalArgumentException. Vetores vazios são válidos e produzem tempo 0. Use valores pequenos na atividade, sem extrapolar o limite de int.

3. Como ler os testes

Cada teste parte de um estado novo. “Esperado” é o resultado definido pelo contrato; “Obtido” é o resultado do seu código. Vários testes podem falhar pela mesma causa. Algumas verificações param na primeira divergência: novos detalhes podem aparecer depois de corrigir uma falha.

Para executar uma missão isolada: sh testar.sh 2 ou, no terminal Windows, testar.bat 2. O relatório mostrará somente os 10 testes selecionados. Rode sem número para voltar aos 30.
